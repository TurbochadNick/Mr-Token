1. `do` has a real executor for exactly one approved tool; every other tool remains advisory.
2. Defaults stay warn-only (`tell`). No config or install path flips a tool to `do` by default.

   - pressure + reclaimable signal;

4. Proxy-disposable handoff stays capped at `tell`, even when policy says `do`.
5. The tool is still protected by 6.7 outcomes: a negative trend auto-disables it before acting.
6. The backend suite is green and includes regression tests for act, no-act, and auto-disable paths.

## Recommended first tool, if Zach approves

Start with **`handoff` only**, and only on explicit `disposable_confirmed`.

Why:
- `handoff` is the only reset/drop action, and the compaction gate work was specifically about
  preventing unsafe resets.
- `confirm_disposable` now binds to the calling session or fails closed, so it can be the explicit
  authorization channel.
- `handoff` already has a deterministic local implementation (`build_handoff`) and does not make a
  network call.
- `compact` is a host action and cannot be executed by the MCP/server code.
- `offload` needs the actual large content/path, which the proc-engine snapshot does not have.
- `confirm_disposable` is itself a consent tool and must never be auto-called.

## Proposed implementation

Add a small auto-act layer inside `intervene.py` or a new `autoact.py`:

```text
maybe_auto_act(session_id, iv) -> iv
```

For v1 it should only recognize:

```text
iv["tool"] == "handoff"
iv["level"] == "do"
iv["phase"] == "escalate"
iv["disposability_source"] == "explicit"
```

Then it may call `build_handoff(None, session_id)` and append the generated handoff to the
intervention message, clearly labeled as the action taken. If any input is missing or the handoff
builder cannot resolve the transcript, return the original intervention with a fail-closed note.

Do not start a new session, run `/compact`, delete context, or change config. The v1 "act" is only
generating the handoff automatically at the escalation point.

## DECISION (2026-07-06, Zach) — build the structure, keep it inert

Green-lit crossing to 6.8, **as a freemium/paid feature**, but **build-only for now — do NOT go
live** (default warn-only; entitlement stubbed so nothing auto-acts until deliberately flipped on).

- **First (and only) wired tool: `handoff`** — the mildest reset (writes a brief; deterministic,
  local, nothing destructive). Zach was unsure which tool; since it ships off-by-default, wiring
  `handoff` commits nothing — the real "which tool to enable" call defers to flip-on time.
- **Monetization: auto-act (L3 `do`) is a PAID feature, freemium.**
  - **3 free auto-act uses, lifetime per install** (a counter in central state, metadata-only).
  - **After the free uses:** degrade to **`ask`** (still fully works — user approves manually) +
    an **upsell prompt**. Never hard-block; never break the workflow.
  - **Free uses double as the 6.7 evidence base** — each free auto-handoff logs did-it-help, so the
    trial simultaneously proves value and stays protected by measure-don't-degrade.
  - **"Paid" verification = a stubbed entitlement flag** (license key / env) for now; real billing
    (Stripe / license server) is a **separate, later project**, explicitly out of scope here.
- **Prompts:** (a) a "try it free — N left" nudge at the escalation point when entitled-by-trial;
  (b) an upsell once the 3 are spent.
- **Still gated by the 6.8-pre safety contract above:** explicit `disposable_confirmed` (never
  proxy) + runway-remains + AFK escalation; proxy-disposable stays capped at `tell`; 6.7 auto-disable
  still applies. The paywall sits ON TOP of those gates, it does not replace them.

**Build target:** the executor + free-use meter + entitlement stub + prompt copy + tests, all
**default-off**. Flipping it live (and the real billing) are separate future decisions.

## IMPLEMENTED (2026-07-06) — built, inert

New module `backend/mrtoken/autoact.py` (`maybe_auto_act(session_id, iv)`), wired into
`intervene.decide()` right after `apply_ask_policy` when `iv["level"] == "do"`. The old
`[auto-action pending — ROADMAP 6.8]` placeholder moved out of `apply_ask_policy` into
`autoact` (which now owns all do-level messaging).

- **Executes only `handoff`** at `do` + `phase=escalate` + `disposability_source=explicit`.
  The action is `build_handoff(None, session_id)` (deterministic, local, no network, no
  new session, no /compact, no deletion) appended to the nudge, labeled. Every other tool
  at `do` stays advisory (`[auto-action pending]`).
- **Freemium meter:** `FREE_USES = 3`, lifetime per install, counted in
  `<central>/state/autoact-meter.json` (metadata only: `used`, `last_tool/session/ts`).
- **Entitlement stub `entitled_paid()`:** true if `MRTOKEN_LICENSE` env is set OR config
  `{"entitlement": {"paid": true}}`. Real billing is a separate later project.
- **Degrade, never block:** paid → always acts; else trial while free uses remain (spends
  one, shows "N of 3 left"); else `spent` → appends an upsell line and leaves the manual
  `handoff` prompt in place. Builder failure fails closed (no free use spent).
- **Still under all 6.8-pre gates** (enforced upstream in `decide()`): proxy-disposable is
  capped at `tell` before it reaches here; runway/near-done suppression and AFK escalation
  gate `evaluate`/`apply_ask_policy`; a negative 6.7 trend auto-disables `handoff` first.
- **6.7 evidence base:** an executed auto-handoff still writes ask-state, so the next
  turn's measure-don't-degrade pass records did-it-help — no extra logging needed.
- **Default-off proof:** with no config `handoff` sits at `tell`, so the explicit path
  never reaches `do` and nothing auto-acts.

Tests: `test_autoact_l3_freemium_executor` (trial-acts+decrements, other-tools-advisory,
first-ask-no-act, spent→upsell, paid-with-0-left, builder-fail-no-spend, auto-disable,
default-off) + a proxy-path `assertNotIn("auto_act")` guard. `./scripts/test-backend.sh`
green (95 tests).

**To flip live later (deliberate future decision, NOT done here):** set `handoff=do` in
config for a real install AND provide the explicit `confirm_disposable` channel. Until
