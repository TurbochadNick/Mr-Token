## Recommended first tool, if Zach approves

Start with **`handoff` only**, and only on explicit `disposable_confirmed`.

Why:
- `handoff` is the only reset/drop action, and the compaction gate work was specifically about
  preventing unsafe resets.
- `confirm_disposable` now binds to the calling session or fails closed, so it can be the explicit
  authorization channel.
- `handoff` already has a deterministic local implementation (`build_handoff`) and does not make a
  network call.
- `compact` is a host action and cannot be executed by the MCP/server code.
- `offload` needs the actual large content/path, which the proc-engine snapshot does not have.
- `confirm_disposable` is itself a consent tool and must never be auto-called.

## Proposed implementation

Add a small auto-act layer inside `intervene.py` or a new `autoact.py`:

```text
maybe_auto_act(session_id, iv) -> iv
```

For v1 it should only recognize:

```text
iv["tool"] == "handoff"
iv["level"] == "do"
iv["phase"] == "escalate"
iv["disposability_source"] == "explicit"
```

Then it may call `build_handoff(None, session_id)` and append the generated handoff to the
intervention message, clearly labeled as the action taken. If any input is missing or the handoff
builder cannot resolve the transcript, return the original intervention with a fail-closed note.

Do not start a new session, run `/compact`, delete context, or change config. The v1 "act" is only
generating the handoff automatically at the escalation point.
