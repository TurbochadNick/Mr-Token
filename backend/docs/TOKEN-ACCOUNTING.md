# Token-accounting definitions

Every token value below is transcript-derived unless explicitly labeled
**estimated**. Do not add values from different rows or labels unless the
definition says they are disjoint.

## Session component sums

`session_summary` sums these fields over the model calls in one recorded
session. They describe observed token activity, not an invoice.

| Display label | Field | Definition |
|---|---|---|
| Fresh input | `input_tokens` | Input that was not served from cache. For Codex, the adapter subtracts cached input from provider input before storing this field. |
| Cache read | `cache_read_tokens` | Cached input re-served to a call. This is throughput and may recur on later calls. |
| Cache write | `cache_write_tokens` | Input used to create cache entries. This is throughput, not a separate model output. |
| Output | `output_tokens` | Tokens generated by the model. `reasoning_tokens`, when present, is a subset of output and is never added again. |
| Fresh input + output | `total_tokens` | `input_tokens + output_tokens`. This measured subtotal deliberately excludes cache read and cache write/create. It is not the cumulative total below. |

The cache-hit ratio is `cache_read / (fresh input + cache read + cache
write/create)`. It is undefined when that input-side denominator is zero.

## Cumulative token total

The displayed **cumulative token total** answers a different question from the
fresh-input-plus-output subtotal. It is shown only with its provenance:

| Provenance | Value | Meaning |
|---|---|---|
| `provider-reported` | Codex provider final total | The provider's final reconciled total for the session. Cached input is already part of the provider input side and is not added separately. |
| `computed-disjoint-components` | Claude component sum | `fresh input + cache read + cache write/create + output`, using documented provider component semantics. This is a computed token total, not a provider-reported total and not dollar usage. |
| `unknown` | no number | There is insufficient evidence for either route. UNKNOWN is preferable to a misleading sum. |

Provider-reported and computed totals are different kinds of evidence. They
must stay labeled, are never silently combined, and do not establish API billing
or realized spend. Dollar estimates appear only for sessions positively verified
as API-metered from their own provider records.

## Current context

**Current context** is not a cumulative session quantity. `status` reports the
latest model call's input side:

```
fresh input + cache read + cache write/create
```

It estimates the context carried by that latest call. The large-context warning
uses the maximum observed input side to avoid threshold flapping; that maximum
does not replace the displayed current-context value.

## Display map

- `why` labels its header subtotal **fresh input + output**, then labels the
  provenance-bearing cumulative total separately.
- `status` prints **cumulative token total** and **context now** separately.
- `report`, `export`, and the UI label the four component sums and call
  `total_tokens` **fresh input + output**.
- TypeScript hook-event counts remain **estimated** char-based values. They are
  not mixed with transcript-derived component sums.
